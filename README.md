# 路線街景影片產生器

填入 Mapillary API token → 選起點與終點 → 選路線 → 產生街景影片。

## 純網頁版（`site/index.html`）
單一 HTML 檔，不需要 Python 或 ffmpeg，影片在瀏覽器內錄製。

- 線上版：https://lish-chen.github.io/ForClaude3/ （repo Settings → Pages → Source 選 **GitHub Actions**，推送到 `main` 後自動發佈）
- 也可下載 `site/index.html` 直接用瀏覽器開啟。

使用：
1. 填入 Mapillary token（只存在你的瀏覽器，請求直接送往 Mapillary）。
2. 在地圖點選或搜尋地址，設定起點與終點，並選擇最多 3 條候選路線之一。
3. 按「產生影片」，完成後預覽並下載（Chrome/Edge 為 mp4，其他為 webm）。

注意：錄製期間請保持分頁在前景；影片時長約為 張數 ÷ 每秒張數，再加上轉彎處的放慢時間（選路線時會預估）。影片已燒入 Mapillary 來源標註（CC-BY-SA 4.0）。

## 叉路標示要走的路
- **標示**：從決策點前約 60 公尺到 10 公尺，畫面上會疊一條半透明綠色路徑，沿著路線往前約 45 公尺，盡頭有箭頭與「走這條」標籤，岔路時會彎向要走的那一邊。
- **只在路口真的出現在畫面裡時才畫路徑**：照片是朝前拍的，視野有限，路口太遠、或側向的路還在畫面外時，畫上去的路徑會落在沒有路的地方。這時改在畫面邊緣顯示「◀ 路口在左側」或「路口在右側 ▶」，已經過了路口就什麼都不畫。
- **提示的距離從照片的拍攝位置算**，不是從路線上的取樣點算，所以「20 公尺後左轉」和畫面實際離路口的距離一致。
- 做法：用路線的座標、照片的拍攝位置與方向，依鏡頭焦距把路線投影到畫面的地面上（假設鏡頭離地約 1.6 公尺、視線水平）。
- 限制：這是幾何估算，GPS 誤差、鏡頭高度與俯仰角都會讓路徑與實際路面有偏移；路徑會蓋在車輛或行人上方，不會被遮擋。以「方向示意」看待，不是精確的車道線。
- 可關閉（進階設定「用綠色路徑標示要走的路」；命令列 `--no-guide`）。

## 方向提示文字
影片在轉彎、叉路、圓環、匝道前後，畫面上方會出現提示條：方向箭頭、距離倒數與要進入的路名，例如「50 公尺後 右轉　進入 中山北路二段」。

- 約在決策點前 80 公尺開始顯示，每 10 公尺倒數一次；到達路口時只顯示動作（例如「右轉」），通過後約 15 公尺消失。
- 支援：左轉／右轉／靠左／靠右／大角度轉彎／迴轉、叉路靠左或靠右、路底轉彎、上下匝道、匯入、進入圓環（含第幾個出口）與駛出圓環。
- 進階設定可關閉（命令列：`--no-cues`）。
- 伺服器版需要能顯示中文的字型：Docker 映像已內建；自行安裝時請確認系統有 Noto Sans CJK 或文泉驛等字型（也可用環境變數 `SV_FONT` 指定字型檔）。找不到時提示條會自動改用英文（例如「In 50 m: Turn right」）。

## 播放節奏：轉彎與叉路放慢
為了讓不熟悉路線的人看得懂，預設播放速度較慢（每秒 4 張影像），並在**轉彎、叉路、圓環、匝道**前後自動放慢：

- 決策點取自路線服務（OSRM）的逐步導航；另外路線上折角超過 25° 的彎道，即使導航沒有列為轉彎，也會放慢。
- 放慢範圍：決策點前約 60 公尺開始漸慢，通過後約 25 公尺恢復；轉彎、叉路、圓環最慢（預設 3 倍，可調 1–8），輕微轉向與匝道約六成。
- 放慢時畫面會停留較久，快換下一張時才溶接，不會出現長時間的重疊殘影。
- 地圖上橘色圓點標出會放慢的位置（網頁版），路線清單會顯示轉彎數與預估影片長度。
- 可在「進階設定」調整播放速度與減速倍數；減速倍數設 1 即恢復等速。

## 只用看得到道路的照片
影片的重點是看得到道路。系統會檢查每張被選中的照片裡，路線該在的位置是不是真的有路，不是就換掉，從該位置其他候選照片重新挑選（最多重複 4 輪）；完成後會顯示避開了幾張。

- **怎麼判斷**：下載每張照片的小縮圖（約 10–20 KB），用照片自己的拍攝位置、方向與鏡頭焦距，把路線前方 5–30 公尺（左右各 2 公尺）投影到縮圖上，看那一帶的像素有多少像路面（灰色或褐色、亮度適中、不是天空藍、不是植物綠）。低於 45% 就換掉。
- **會被擋掉的情況**：鏡頭仰起拍到天空、拍到牆面或樹叢、前方被大型車輛擋住、鏡頭傾斜到路面跑出畫面外。另外也會單獨檢查畫面是否大半是天空（與畫面上緣相連的平滑藍色或白色區域）。鏡頭微幅下俯但路面還在畫面內的照片會保留。
- 不靠 Mapillary 的拍攝角度資料（那是相對整段重建的方向，不是可靠的絕對俯仰角）。360° 全景圖不受影響。
- 進階設定可關閉（命令列 `--any-view`）。
- **限制**：這是啟發式判斷，用合成圖測過，還沒有在大量真實照片上調校。GPS 或方向誤差大時，投影的位置會偏，可能誤擋好照片；沒有候選照片通過時，該位置就變成「沿途沒有街景」，不會勉強用看不到路的照片。白色或米色牆面、顏色與路面接近的場景可能漏判。誤判或漏判的畫面請告訴我，可以調整門檻。

## 道路連續性（純網頁版）
不同拍攝者、車道、鏡頭與時間的照片拼在一起，道路會在畫面裡左右跳動。網頁版用三個方法降低這個問題：

1. **整段路線一起挑照片**：不再逐點挑「最近的一張」，而是用動態規劃找出整條路線的最佳照片鏈，盡量留在同一段拍攝（sequence）內；換拍攝來源、換日期、換方向都要付出代價。
2. **道路方向平滑**：行進方向取前後約 25 公尺的平均，路線轉折點不會讓畫面忽然轉向。
3. **路線對齊**（預設開啟）：依「路線方向 − 照片拍攝方向」把畫面水平平移，讓道路方向落在畫面中央；平移量依 Mapillary 提供的鏡頭焦距換算，並限制在裁切範圍內。
4. **全景轉正**（選用）：360° 全景圖可以直接轉成朝向路線的視角，不受拍攝方向影響，但解析度較低、處理較慢。

限制：只能修正「方向」的偏差；不同車道造成的橫向位置差、鏡頭高度不同，無法完全消除。沿途照片本來就是來自同一段拍攝時效果最好。伺服器版（`server/`）也有同樣的改進，用 Pillow + numpy 實作（`server/align.py`、`server/core.py`）；命令列可用 `--no-align` 關閉對齊、`--allow-pano` 啟用全景轉正。

## 伺服器版（`server/`，Flask + ffmpeg）
```bash
cd server
pip install -r requirements.txt     # 另需安裝 ffmpeg
export MAPILLARY_TOKEN='MLY|...'    # 可省略，改在網頁上貼
python app.py                       # http://127.0.0.1:8000
```
任務佇列、進度與取消、mp4 預覽下載；亦有命令列 `route_video.py` 與 Dockerfile。測試：`pytest tests`。
預設只綁 127.0.0.1；對外開放前請自行加上認證。
