# 睡眠紀錄感測器可行性評估

目標:把台大睡眠中心「睡眠日記」表單做成 App,以使用者自填為主;夜間部分評估能否用手機感測器自動記錄,讓使用者**不必看時間**。

## 一、表單欄位與資料來源

| 欄位 | 能自動取得? | 建議做法 |
|---|---|---|
| 日期、星期、工作日/休息日 | ✅ | 系統日期;休息日預設週末,可改 |
| 就寢時間(躺上床) | ⚠️ 半自動 | 睡前按「我躺上床了」 |
| 嘗試入睡時間 | ✅ 半自動 | 按「關燈,準備睡覺」 |
| 睡著所需時間 | ❌ 無法精準 | 本人睡著當下無法標記;早上憑感覺填(可用穿戴裝置預填) |
| 醒來次數、總醒來時間 | ✅ 翻面(本原型) | 翻面起訖,早上確認 |
| 最後醒來時間 | ✅ 翻面 | 最後一次翻起來沒翻回 |
| 起床時間 | ✅ | 長按「起床」 |
| 睡眠品質 1–5、鬧鐘、備註 | ❌ 主觀 | 使用者填 |
| 小睡、酒、咖啡因、藥物、照光、運動 | ❌ / 部分 | 使用者填;小睡/運動可日後接健康資料 |

## 二、你提出的「翻面」做法

**語意定義**(原型採用):螢幕朝下 = 睡眠中;翻成朝上 = 醒了;翻回朝下 = 重新入睡。
(你原本的說法是「翻面=起床離床」,但表單要的「醒來次數/時間」包含躺著醒著,所以用「醒了/再睡」更貼合,離床與否不影響填寫。)

**優點**
- 不需看螢幕、不需看時間;是有意識的動作,比被動偵測準確。
- 靠重力方向(加速度計 z 軸),不依賴麥克風/相機,隱私與耗電都低。
- 能正確記錄「醒來的時刻」與「決定再睡的時刻」。

**限制(要誠實面對)**
1. **睡著的時刻永遠無法自己標記**。翻回朝下只代表「我要再睡了」,不是「我睡著了」。所以「醒著的時間」只是下限,入睡潛伏期仍需早上估計。
2. **半夜迷糊可能忘記翻** → 早上畫面一定要能一鍵修正,並顯示翻面時間軸供回想。
3. **誤觸**:拿起手機、碰撞、床震。原型以「放平且穩定停留 2.5 秒」才成立,並以低通濾波,避免誤判。(已用模擬資料測試。)
4. **平台差異**:iOS 與 Android 的 z 軸正負號相反,故以「開始時的朝向」當基準而非絕對朝上/下。
5. **螢幕朝上會亮**:朝上時螢幕本身要純黑、不顯示時間;建議「朝下=睡覺」。
6. 放床頭櫃/充電、不放在床墊上,否則翻身會晃動(可調 holdMs)。

## 三、最大的技術限制:鎖屏後感測器會停

| 平台 | 整夜背景讀取感測器 | 說明 |
|---|---|---|
| **網頁/PWA(本原型)** | ❌ 鎖屏或切到背景後 JS 與感測器停止 | 折衷:接充電器 + Wake Lock 保持螢幕開著、畫面純黑(OLED 幾乎不耗電) |
| **Android 原生** | ✅ 前景服務(foreground service)+ 重力/加速度感測器,螢幕可全關 | 最推薦;需通知列常駐、豁免電池最佳化 |
| **iOS 原生** | ⚠️ App 進背景會被暫停,Core Motion 不能整夜背景讀取 | 常見做法:背景音訊模式(播放靜音)續命,或改依賴 Apple Watch / 健康資料 |

> 結論:**網頁版可做示範與短期試用;要「整夜不開螢幕」的穩定版,Android 用原生 + 前景服務,iOS 較難,建議搭配穿戴裝置。**

## 四、其他不必看時間的方案(依推薦度)

1. **穿戴裝置/健康資料匯入(最推薦的補充)**:Android Health Connect、Apple HealthKit 的睡眠資料,預填就寢/起床/中途醒來,使用者只需確認。被動、不需任何動作。
2. **手機使用軌跡當線索**:充電器接上時間≈上床;夜間解鎖/亮屏時間=確定醒著(因為你在用手機);早上第一次解鎖≈起床。零操作,但只是旁證。
3. **床墊放手機做動作偵測(類 Sleep Cycle)**:可估睡眠階段與翻身,但手機 actigraphy 對「躺著醒著」判斷差,醒來時間易低估,不適合當日記主資料,只當預填參考。
4. **麥克風(鼾聲/環境聲)**:耗電、隱私敏感、效益對日記欄位有限,不建議。
5. **其他無螢幕觸發**:音量鍵(僅原生)、Pixel「輕點背面」、床邊 NFC 貼紙——可作翻面之外的備援標記,但各機種支援不一。

## 五、建議路線

1. **現階段**:使用本原型(`index.html`)——自填表單 + 翻面標記 + 手動按鈕備援,先驗證翻面這套操作習慣是否好用。
2. **下一階段**:包成 Android 原生 App(前景服務),夜間不需開螢幕;同時接 Health Connect 預填。
3. **iOS**:先以網頁版(螢幕純黑 + 充電)或手動標記 + HealthKit 匯入;原生整夜翻面偵測需額外驗證。
4. 所有自動資料一律標示「自動帶入」,**早上讓使用者確認/修改**——日記的目的是主觀感受,不是取代睡眠檢查。

## 六、檔案

- `index.html` / `app.js`:原型(純前端,資料存 localStorage,可匯出 CSV、列印 7 天週表)
- `flip.js`:翻面偵測與夜間彙整(純函式)
- `test/flip.test.js`:`node test/flip.test.js`

試用:在 `sleep-diary/` 執行 `python3 -m http.server`,手機同網路開啟。感測器需 **HTTPS**(或 localhost)才會授權,實機測試可用 GitHub Pages 或 `ngrok`。
